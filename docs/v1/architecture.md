# Architecture and engineering rules

## Planned module and packages

Future Go code is module `github.com/trogers1/sidecar-comments`, Go 1.27.1 via `mise`. Planned boundaries are `cmd/sidecar` and `internal/{cli,domain,format,operations,store}`. Dependencies point inward only: command → CLI → operations → domain; CLI → format/store; store → format/domain; format → domain. Domain imports no sibling internal package. Neovim Lua and contract runners invoke the executable only. No production, test, fixture, subprocess, CI, or runtime code accesses `../config`.

`domain` owns constructors and immutable typed values. `format` owns byte parser, repair AST, canonical encoder, and metadata token validation. `operations` owns pure sequential semantics. `store` owns secure filesystem transactions. `cli` owns standard `flag` command parsing, DTO boundaries, envelopes, and exit mapping. Standard `flag` is mandatory unless a documented failing requirement proves it inadequate; no general CLI framework is allowed by default.

## Trust boundaries and code principles

File bytes, flags, stdin, JSON, and Lua output are untrusted. Decode them into concrete DTO structs, validate tokens/duplicate keys/schema/version/limits, then call constructors. Ordinary checked byte/string conversion and `encoding/json` to concrete DTOs are allowed. Production code MUST NOT use `unsafe`; `any`; `map[string]any`; unchecked named-type conversion from untrusted values; reflection-based domain dispatch; trust-boundary type-assertion dispatch; or nonexhaustive tagged-union switching. Use explicit branches for every closed-union tag and fail unknown values.

Prefer small pure functions, immutable values, explicit errors, bounded streaming reads, and dependency injection only for clock/randomness/filesystem failure tests. Do not hide failures with defaults, retries beyond specified bounds, silent normalization, recovery, or compatibility behavior. Comments explain invariants and security reasons, not restate syntax. Error strings exposed by protocol are stable symbols, while OS detail stays out of the contract.

This contracts-only checkout has one direct external dependency: exact-pinned `github.com/santhosh-tekuri/jsonschema/v6`, only in `contracts/runner` to meta-validate checked-in Draft 2020-12 contracts and observed child protocol output, and in the tiny test-only `tests/cli/schema_test.go` validator of the normative public schema. Its tidy-resolved indirect dependency `golang.org/x/text` is also harness-only and does not authorize a production import. The contracts runner's authorized generic JSON bridge is `contracts/runner/schema.go`. It receives a generic tree only after `decodeJSONCorpus` or `decodeJSONGolden` has independently completed strict concrete DTO decoding (or after the runner's strict compact-envelope check for observed child output); it returns only validation errors, never generic data; and it makes no type assertions or domain decisions. Generic JSON is forbidden as a DTO decoder and everywhere outside that contracts-only adapter and the narrow `tests/cli/schema_test.go` exception, including all present and future production code. The CLI test adapter may pass an inferred generic JSON value only to `schema.Validate`, returns only errors, and exposes no generic data or domain decisions; it makes no type assertions. Schema validation does not replace the independent lexical, concrete DTO, or domain checks required for public CLI observations. Production code has no external dependency yet. When production NFC verification is implemented, it MAY promote `golang.org/x/text/unicode/norm` to an exact-pinned direct dependency exclusively for that verifier, with its version/checksums and Unicode data version recorded then. If standard library cannot meet a required descriptor-relative filesystem capability or advisory lock, writer support hard-fails rather than adding a dependency or unsafe fallback.

## Automated boundary checks

`make check` rejects forbidden production patterns (`unsafe`, reflection dispatch, `any`, `map[string]any`, runtime `../config` access), invalid package dependency direction, non-pinned/misused external imports, generated schema/golden drift, unformatted Go, and module tidy drift. `TestArchitectureBoundaries` mechanically reserves generic JSON spellings to the single contracts adapter and reserves `jsonschema` imports to that adapter and the exact test-only path `tests/cli/schema_test.go`; no other test or production path receives the exception. Contract tests must not import `internal` packages or private APIs.
