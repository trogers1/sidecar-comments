## Definition of done

1. Every externally observable normative v1 branch is accounted for in a clause-to-proof inventory: either an **executable, byte-exact fixture against `SIDECAR_BIN`**, an explicit **supplemental test** for a property impossible to observe at the executable boundary, or a narrowly cited **not-applicable** entry. No broad `BHV-RED-*` label or manifest row counts as proof merely by existing.
2. **Most tests invoke the actual `sidecar` CLI and inspect what it prints and what happens to `.comments` files.** For example: create a source file, invoke `thread create` or `apply`, check exit/output, parse the resulting sidecar through `validate`/`thread list`, and assert its contents and revisions; update/delete then assert changed bytes or unlink. The suite runs against **any independently supplied compatible binary**, without importing `internal/`, assuming a Go implementation, calling private methods, or matching implementation-specific temp names/call counts. JSON Schema and fixtures validate the real CLI boundary. Assert exact sidecar bytes where canonical serialization is itself the public contract; otherwise prefer semantic CLI results and resulting file state over incidental layout or transient events. No implementation code is required for the suite to be *finished*: before a conforming binary exists, its mandatory executable tests should fail as **red conformance**, not fail because the runner cannot express or execute them.
3. The real Neovim 0.12 adapter is tested at its public `setup`/commands/state/UI boundary in headless Neovim, with a real Sidecar binary for integration and controlled process responses where scheduling is needed. No direct calls to private Lua functions or format parsing in Lua tests.
4. `make check`/`release` can eventually become green **only** when all obligations are proven by executed fixtures, supplemental property/race/editor gates have run, and required schemas/artifacts are fresh. Zero unresolved entries is permitted, but never sufficient by itself. An unavailable capability is a nonzero failure, never a skip or pass. Until production exists, `make preimplementation-check` remains the only green harness-only gate.
5. Prove the runner can reject independently corrupted exit code, stdout, stderr, protocol DTO, final bytes, mode/link, lock state, timeout, and unsupported/unavailable capabilities using controlled test subjects. Test the full release gate on supported macOS arm64 and Linux amd64 and from a fresh clone.

**Language caveat:** The *behavioral* CLI/editor corpus should survive a complete rewrite in another language. The current normative `docs/v1/architecture.md`, toolchain docs, and `plans/initial.md` also require Go 1.27.1, named `internal` packages, Go fuzz/race/vet/gofmt, and a specific NFC dependency. A non-Go implementation cannot satisfy those **implementation-policy** requirements unchanged. Keep those gates separate from public conformance; if language-independent *release* conformance is desired, obtain an explicit versioned decision/amendment rather than silently dropping Go-only requirements.

## Test-design rule for this work

Aim for a **CLI-first pyramid with a wide top**, not a unit-test pyramid: (1) public CLI flows asserting stdout/stderr, exit status, `.comments` creation/change/deletion and CLI-readable thread state; (2) a smaller set of public CLI edge cases for exact grammar/errors/security; (3) only the few supplemental property/fault tests that cannot be made observable at the process boundary. Do not test constructors, parser methods, lock-helper calls, or private Go/Lua symbols as substitutes for a CLI contract. Treat controlled orchestration as a way to arrange *external* inputs and timing around the real CLI, not as a mock of its internals. Keep expected results grounded in docs/schema and checked-in sidecar goldens, not duplicated production logic.

### B. Make pending scenarios runnable in a portable contract DSL

Version the **executable** corpus/fixture schema (do not weaken v1 or treat the v2 *design* schema as a runnable fixture). Prefer a **multi-step public CLI scenario** over one fixture per internal branch: initial source/sidecar state → one or more real `sidecar` invocations → exit/output assertions → final `.comments` bytes/existence and optional follow-up `validate`/list/get assertions. This can test create→reply→edit→delete, format idempotence, or apply rollback with no access to implementation packages. Keep single-invocation cases for isolated input/error boundaries. A normal case is initial FS + argv + stdin + expected status/streams + final FS. Controlled cases add only typed, implementation-neutral arrangements: deterministic byte producers; independent child actors, readiness barriers and release order; held advisory locks and phase-bound object replacement; supported host object/umask/credential setup; reproducible fault conditions; editor process and response scheduling. Each typed input needs an independently tested adapter, explicit observables, cleanup/timeout bounds, and a **nonzero unavailable** outcome if unsupported. Never accept arbitrary JSON schedules or a substring-based `fixture_version` discriminator as runnable evidence. Expand fixture FS kinds/modes/path alphabet as needed for FIFO/socket/device, legitimate Unicode/space paths, mode preservation, umask, and identity assertions. Test runner self-rejection with deliberately bad subjects, bounded output/descendant handling, permission behavior under ordinary and privileged users. Keep literal base64 payloads uninterpreted even when containing `{{...}}`.

Do **not** bake private fault hooks into the portable compatibility corpus. If a failure cannot be induced/observed through supported external controls, record a targeted **supplemental** fault/property test with an explicit public-boundary limitation and a separate required release gate. The portable suite must still exercise observable outcomes for failures it *can* induce. Limit-plus-one output proves rejection, not bounded allocation; add an external memory/I/O observable where practical or justify a supplemental bounded-read test. UUID output shape is not proof of clock monotonicity, collision count, or CSPRNG failure: schedule/test those separately and state what each test establishes.

### C. Turn every behavior family into direct executable proof

Favor **end-to-end flows through the real binary** that cover several related behaviors by inspecting CLI output and resulting `.comments` files; add small focused negative/boundary fixtures for distinct rejection classes. Do not force every test to compare raw bytes when the behavior is better expressed as a valid thread/message visible through public `thread list`/`thread get`. Compare exact bytes for the canonical format, revision hashes, untouched-on-failure guarantees, and changes whose exact framing is specified. Required matrices:

- **Format/read/repair:** every grammar terminal, role and closed metadata union, nested duplicate/wrong-token/unknown/escape/surrogate cases, raw UTF-8/HTML encoder bytes, canonical sorting, all framing permutations (internal blanks and trailing logical LFs), every reserved-prefix and malformed structural line, empty/missing/zero/whitespace behavior, enumerated formatter-only variants and `--check`, populated validate/list/get and revisions, repair-only missing user/bot ID, diagnostic offsets/order, fix/check/retry, invalid legacy fail-closure.
- **Input/domain/source:** all UUID lexical/version/variant/nil/namespace/uniqueness cases and generated-ID failure/monotonicity properties; author/GitLab variants, NFC/control/White_Space scalar boundaries and cross-language Unicode cases; body-file **and stdin** transport BOM/NUL/UTF-8/CR/CRLF/mixed endings/exactly-one-final-LF/blank-body and apply's already-logical body; source existence/type/size/endings, byte/rune coordinate boundaries and anchors including CRLF/multiline, `lost` exemption, implicit source pre-lock **and locked revalidation** for create/move/apply. Assert every documented size/count limit and limit+1, raw metadata limit, and request-vs-target exit distinctions.
- **CLI/protocol/mutations:** command flags/placement/repetition, stdin arbitration, output `text|json|id|none`, exact single-LF/no-JSONL channels, every result/error DTO and check-state exit, error precedence table across sidecar/source/body/metadata/operations paths. Cover create explicit/generated/retry/collision, move/update equal no-ops, deletes and last-message unlink, revision guards, `if-last-author-kind`, all six apply DTOs, sequential working-copy semantics, duplicate/retry/delete→recreate, indexed failure/atomic rollback, operation/document limits. Do not mistake one happy-path `V1-CLI-APPLY` fixture for apply completeness.
- **Secure storage/concurrency:** target and lock symlink/directory/hardlink/nonregular classes; no-follow parent/target/lock/temp, modes/new-file umask, persistent lock reuse/timeouts; temp collision bound, precommit identity change, pre- and post-rename/unlink failures (including close/unlock/identity/cleanup), fsync uncertainty and `commit_may_have_succeeded`; independent **process** races for revision, lock serialization and no lost successful updates. Observe final state and both process responses; no implementation-private mutex/call-counter assertions.
- **Neovim:** headless 0.12 public setup/options/idempotency, eligibility, binary/version/health, commands/states/events, list/extmark selection/navigation, half-open UTF-8-byte visual ranges, dirty source/sidecar fail-closure, repair confirmation, stale async response discard, external changes, no automatic revision-conflict retry. Drive public editor commands and inspect visible buffer/marks/state, not Lua parser internals.

For parser robustness/property coverage, use arbitrary-byte CLI `validate`/`format` campaigns first; assert no crash/hang and exact public behavior. Where parse→serialize→parse semantic equivalence or UUID clock/RNG injection truly cannot be established through the CLI, require a small justified supplemental property test. Seed from *all* canonical, formatter-only, repair, and malformed corpus fixtures. If an alternate-language implementation is used, provide equivalent supplemental tests without making the portable corpus depend on its internals.

### D. Build an honest proof-aware release gate

Add `pending|proven|not_applicable` states with a closed schema and explicit proof references to **registered runnable** fixtures and supplemental gate IDs. Schema validation is proof **eligibility**, not an observed pass: a fixture counts only after execution against the supplied binary in this invocation. Test transitions, stale/orphan/duplicate proof refs, unknown capability, N/A citation, missing mandatory row, zero pending with a skipped suite, and a passing fake subject that omits one required branch. `full-red` should list *unresolved* cases; when none remain, still require binary execution and every supplemental suite. No hand-edited coverage percentage or deleting a red pack to make the gate pass.
